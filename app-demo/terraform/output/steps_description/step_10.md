# Step 10: main.tf (completamento) — Generazione File .env

## Goal

Complete `main.tf` by adding the `local_sensitive_file.dotenv` resource that generates a `.env` file containing all infrastructure outputs, including secrets (database password, Keystone user passwords, SSH key path). This file serves as the single source of truth for connecting application components to the infrastructure.

## Rationale

- **`local_sensitive_file`** instead of `local_file` — The `.env` contains sensitive values (DB password, Keystone passwords). Using `local_sensitive_file` prevents the content from appearing in `terraform plan` output and state diffs, and sets restrictive file permissions (0600).
- **All secrets centralized in `.env` only** — Following the requirement that secrets must never be hardcoded in source code or exposed in Terraform outputs. The passwords are generated by `random_password` resources and referenced only here and in the Keystone user resources.
- **Heredoc (`<<-EOF`)** — Provides a readable multi-line template with clear section headers matching the original AWS `.env` format. The `-` in `<<-EOF` strips leading indentation.
- **References to all domain files** — The `.env` aggregates outputs from network.tf (floating IPs), compute.tf (instance IPs), storage.tf (Swift container, Keystone users/passwords), loadbalancer.tf (VIP), and variables.tf (DB credentials, SSH path). This creates an implicit dependency on all resources being created first.

## Alternatives

1. **`templatefile()` with an external template** — Would separate the template from the resource definition. Unnecessary complexity since the template is tightly coupled to the resource references and is only used once.
2. **Regular `local_file`** — Would expose secrets in plan output. Rejected for security reasons.
3. **Separate `.env` files per domain** — Would fragment the configuration. A single file is easier for applications to consume.
4. **Terraform outputs for secrets** — Would expose sensitive values in `terraform output` and state file. Rejected per requirements.
